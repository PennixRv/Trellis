# Teamwork 输入与结果整改增量合同

本合同承接当前任务的 Teamwork 实施范围，基础设计见 `design.md`。根侧权威审查、决策和实施顺序见 `../../../../../.trellis/tasks/in_progress/10-29-new-fork-workflow-master-plan-v2/research/teamwork-provider-input-and-control-audit.md` 与同目录 `teamwork-input-result-remediation.md`（从本文件所在目录按实际根仓位置定位）；这些引用说明协调来源，不作为 CLI 自动加载的任务相对资产。

用户要求对全部已知审查缺口修复并发布重装；本轮明确选择保留默认文本兼容、代理强制机器视图，并再次要求无沙箱、无权限强制、自动允许，通过提示词提醒边界。复用条件实施授权，不将权限硬限制或工具准入加入范围，不调用 Teamwork teammate 修复自身机制。

实施按 W1 启动与终态收束 → W2/W3 公共角色与模式输入、参考数据分层 → W4 版本化内容报告与共同机器回执 → W5/W6/W7 后端能力、自动允许、多轮与恢复 → W8 测试/Skill/模板/文档 → 原生发布重装的顺序推进。FIFO、容量、期限、重试、取消及持久化 disposition 归 CLI；主代理负责语义接受。保留旧报告及冻结任务合同，不把旧文本冒充新结构校验通过，不复制根侧第二份源码。
