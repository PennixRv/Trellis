# Implementation plan

## Preconditions

- The root coordinator and this owner task must be sealed and explicitly approved at their current revisions before implementation resumes. Both were returned to planning to resolve the post-closure change-path contract.
- Target branch: `pennix/v0.7-beta`.
- Baseline receipt: `research/01-pre-migration-baseline.json`; it freezes exactly 21 pre-existing active tasks and confirms the nested Marketplace has no reachable objects missing from the root checkout.
- Keep every `.py` change synchronized between `.trellis/scripts/` and `packages/cli/src/templates/trellis/scripts/`.

## Ordered steps

1. Update the workflow-state and command specs with the approved stage table, status/stage invariants, material schemas, model-owned minor/major criteria, execution-ledger contract, migration contract, and native command ownership.
2. Implement stage validation and atomic persistence in the shared planning module; add constrained advance/digest behavior and bind seal, approval, start, replan, and archive to the same revision. Preserve replan from any `in_progress` task, including legacy tasks without a recorded stage, and add replan from `planning/plan_closed`; reject archived/completed terminal tasks; record source status, nullable source stage, and target stage, increment revision, clear old receipts, and keep CLI validation separate from model impact classification.
3. Implement the complete-plan validator for decision and implementation blocks, including order/dependency, owner, verification, and unique stop-point checks.
4. Add task migration dry-run/apply/receipt/conditional rollback and fixtures. Do not apply it to the 21 baseline tasks yet.
5. Update create/status/context and replan paths so the CLI is the only stage writer and displays the current stage without conflating it with `task.status`. Verify `execution.md` is excluded from the approved plan digest.
6. Replace the brainstorm template with the single closed-plan Skill; update commands, workflow, Hooks, session utilities, platform callers, and tests. The model routes independent deliverables to new tasks without changing unrelated active tasks, clarifies an unresolved task relationship without mutating the current task, and creates a new task for follow-up after terminal completion. It assesses current-task post-closure planned work against its approved plan and `direct_ready` work against its accepted bounded direct contract: a small request that changes approved scope or acceptance is major; minor deltas append evidence and verification to `execution.md` without a state transition; major or unbounded changes stop dependent implementation, select the earliest affected stage, invoke native replan, and require a new reviewed plan and explicit approval/reclassification. Add hash-safe removal for old generated files and preserve unowned or modified files.
7. After the root gate is implemented, remove the nested Marketplace submodule and module store, retain `docs-site`, and update CI/publish checkout behavior.
8. Run focused CLI/template/migration tests, full Trellis lint/type/Python/build/test checks, script-tree parity, and all submodule checks. Record receipts in this task.

## Stop point

Stop when the Trellis state contract, native CLI guards and migration interface, model-owned minor/major routing, execution ledger behavior, single-entry routing, safe generated-asset migration, and Marketplace submodule/CI changes are implemented on `pennix/v0.7-beta` and all Trellis-owned checks pass. Tests must prove that both `planning/plan_closed` and `in_progress/plan_closed` can replan to an explicit earlier stage, old approval cannot start after replan, and an execution-ledger append preserves the current approval. Do not apply the 21-task migration or pin/commit this component until the root coordinator reaches its corresponding ordered steps.
